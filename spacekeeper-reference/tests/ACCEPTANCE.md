# 验收清单（不限语言、不限绘图库）

## A. 一致性：餐桌
输入 `examples/dinner.scene.json`：
- `shot_south`：画面左甲，远处中央乙，右丙，空座近景方向。
- `shot_east`：南侧空座在画面左，远处中央甲，画面右乙，近景丙。
- 若生成图中甲和丙无因对换座位：`fail`，须报告哪个实体、预期/实际关系；不可改 JSON 去迁就。
- 若特写裁掉人物，且该镜头没有列为 `must_show_ids`：不能仅凭缺席判 `fail`。

## B. 关系：院子
输入 `examples/yard.scene.json`：
- 东墙、北树、南池塘的世界方位不随镜头变化。
- 南机位：东墙方向在画面右；北树偏远，南池塘偏近。
- 西机位：北树在画面左侧方向，南池塘在画面右侧方向，东墙偏远。
- 小狗只知道“靠东墙”，并不知道在东墙的南段或北段：不能推断其确切画面横向/纵向坐标；有必要就给出模糊约束。
- 大树偶然被画面裁掉，不应自动判地标漂移。

## C. 剧情状态
向餐桌场景追加 `shot_03`，并在其前添加：
`{"before_shot_id":"shot_03","entity_id":"person_a","new_location":{"relative_to":"chair_s","relation":"at","certainty":"given"},"reason":"剧情中甲明确换到南侧座位"}`
- `shot_south`、`shot_east` 的甲仍在西侧；`shot_03` 的甲才在南侧。
- 旧镜头不回溯改写。

## D. Agent 换手
将 `*.scene.json` 交给一个未读过原对话的新 Agent：
- 能直接识别世界轴、每个稳定实体、各个镜头机位与事件。
- 能区分给定事实、推断事实和未知信息。
- 能按统一数据继续新增镜头，且不会因为换人、换 Image 模型、换绘图工具而重建不同的物体身份。

## E. 不追求
不按厘米、像素、镜头真实焦距、精确 3D 遮挡打分。优先避免普通观众能感知的明显位置/身份矛盾。
