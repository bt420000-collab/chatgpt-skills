# SpaceKeeper · 参考图空间场记

## 何时使用
同一场景需要多个机位、连续参考图、角色或道具相对位置保持一致时使用。单张无连续性要求的图片可以跳过。

## 权威数据
- 每个场景维护 **一份** `*.scene.json`；结构见 `spec/scene.schema.json`，语义见 `spec/CONTRACT.md`。
- 世界坐标永不随镜头旋转：**东 = +x，北 = +y**；平面图北在上。
- `entities[].id` 是永久身份，不因换机位、改构图、换模型、换 Agent 而改变。
- `entities[].location` 是场景事实或显式不确定性；`shots[].camera` 是镜头决定；`shots[].space_prompt` 和 `review` 是可丢弃的派生结果。
- **生成图不能自动反写权威场景。** 仅剧情变化（`events`）或明确纠错才更新事实。

## 标准作业流程
1. **读场景**：先看已有 `*.scene.json`。新场景只抽取影响连续性的角色、重要物件与环境锚点；未知不填成确定事实；检查实体 ID、镜头 ID 唯一且引用有效。
2. **定镜头**：新增/修改 `shots[]` 的 `camera.position`、`camera.target`、`framing`、`focus_ids`；可自行画俯视图，但图不是权威文件。
3. **算投影**：以镜头朝向计算各实体的左/中/右、近/远、视线及可能遮挡；使用 `events` 形成镜头时的实体状态。不要把世界方向直接当画面方向。
4. **写空间提示词**：仅描述本镜头与剧情有关的空间关系；与角色/画风提示词分开，避免不相干细节塞满上下文。
5. **看图检查**：视觉 Agent 根据图像报告已观察到的关系；与投影结果比较，只拦截观众能察觉的身份错位、座位交换、地标颠倒、无因移动。无法看清则标为 `uncertain`。
6. **迭代**：若 `fail`，修当前镜头提示词或重生图；不得为了迁就错误图改写场景事实。确认剧情移动时写 `events`。
7. **交接**：保留场景 JSON 与参考图路径即可。下个 Agent 先读该 JSON 再继续工作，勿依赖上一 Agent 的长对话。

## 投影的确定性规则
对于摄影机位置 `C` 和看向目标 `T`，`F = normalize(T-C)`，画面向右向量 `R = (F.y, -F.x)`。某实体位置 `P` 相对镜头：
- `dot(P-C, R) < 0` → 左；`> 0` → 右；接近零 → 中；
- `dot(P-C, F)` 越小 → 越近，越大 → 越远；不在镜头前方的不应硬判可见。
- 上下不是世界南北的直接映射；受景别、俯仰角、透视和遮挡影响，不能只凭俯视图作硬结论。
- 对 `relative_to + near` 等模糊关系，只输出能证实的粗略约束；不要杜撰精确站位或图像中的实际可见性。

## 日常制作的取舍
- 精确尺寸、焦距、3D 建模、深度图、像素级对齐都**不是前置条件**。
- 不强制任何实现技术：ASCII / SVG / Canvas / 手绘 / 自定义程序均可；它们都读同一种 JSON。
- 不要每个镜头创建新场景；同一场景只换机位。允许合理的构图形变。
- 未明确需要的东西可以不入图、不检查。

## 输出约定
- **必备**：`<scene_id>.scene.json`（唯一真相源）。
- **按需**：工具产生的俯视图、参考图片、校验报告；路径可写入 `shots[].reference_image`，校验摘要可写入 `shots[].review`。
- **镜头空间提示词**：可写入 `shots[].space_prompt`；变更空间事实或摄影机后必须重算，不可把旧提示词当真相。

## 快速验收
运行或推理 `examples/dinner.scene.json`：南机位应为 **甲左、乙远处中央、丙右**；东机位应为 **空座左、甲远处中央、乙右、丙近景**。详见 `tests/ACCEPTANCE.md`。
